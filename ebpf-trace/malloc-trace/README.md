# malloc/free DWARF 学习测试

这个目录用于学习 BPF 采集和 DWARF 解栈。`memleak.bpf.c` 跟踪指定进程的
`malloc/free`，`memleak.py` 在采集期间保存原始事件，每新增 1000 条记录时
仅做分配与释放配对清理，移除已确认释放的记录。按 Ctrl+C 停止后才解栈并输出
最终结果，没有后台解栈线程和定期报告。

## 运行

需要原生 x86-64 Linux 或 WSL2，内核 5.12 及以上，以及：

- 发行版提供的 BCC Python 绑定和对应内核头文件，例如 Debian 的 `python3-bpfcc`。
- elfutils 的 `libdw.so.1` 和 `libelf`。
- 加载 BPF、安装 uprobes 的权限，通常使用 root。
- 目标及调用链中的 ELF 文件具有 DWARF CFI，通常在 `.eh_frame` 中。

在本目录运行已有测试程序，再启动采集：

```bash
./test &
target_pid=$!
sudo python3 memleak.py -p "$target_pid"
```

`test.cpp` 的目标负载为每秒 10,000 次 malloc，每 10 ms 执行 100 次，
轮流经过 64、256、4096 字节的三条分配分支，普通分配立即 free。
持续每秒最多故意泄漏一次 1024 字节分配，泄漏分配也计入上述次数；
每秒新增泄漏不超过 1 KiB，累计泄漏量不设上限。
程序每秒输出实际 malloc/s 和累计泄漏字节；负载无法按时完成时，按实际能力运行。

等待目标程序执行一段时间后，**在采集器所在终端按 Ctrl+C**。采集器停止探针、
读取剩余事件，再按调用栈汇总仍未释放的分配。

只保留三个参数：

| 参数 | 含义 |
|---|---|
| `-p / --pid` | 必填，目标进程 ID |
| `--obj` | malloc/free 所在的 glibc 名称或路径，默认 `c` |
| `--stack-bytes` | 每次采集的栈字节上限，默认 16384（16 KiB），允许 1 到 32768 |

例如指定 libc 路径和较小的栈快照：

```bash
sudo python3 memleak.py -p "$target_pid" \
    --obj /path/to/libc.so.6 --stack-bytes 8192
```

ring 容量和展开深度直接使用 `memleak.py` 顶部的常量：
`MALLOC_BUFFER_MB = 64`、`FREE_BUFFER_MB = 4`、`MAX_FRAMES = 127`。

## 数据流程

1. malloc 入口按线程保存申请大小，返回时取出并删除。
2. 每次成功 malloc 都尝试采集寄存器和用户栈，直接向 malloc ring 预留、填写并
   提交一条完整记录；free 向独立的 free ring 提交一条小记录。
3. Python 复制事件时直接读取序号、类型和地址，`records` 保存
   `(sequence, kind, address, data)`，其中 `data` 是有效事件字节。
   每新增 1000 条，就按序号排序，从上次已处理的序号继续遍历连续部分：malloc 按地址
   保存，free 删除对应分配，只留下该部分仍存活的 malloc。遇到序号缺口立即停止，
   当前及后续记录原样保留，等缺失事件到达后的下一次清理再处理；新增计数归零。
   采集中不解栈、不输出报告。
4. Ctrl+C 后停止探针并排空两个 ring，再清理一次剩余记录。
5. 仅对最终仍未释放的分配同步执行 DWARF 解栈，按调用栈归类，汇总每组的总字节数
   和分配次数。各组按总字节数从大到小排列，每组只输出一份调用栈。

归类依据是完整的栈帧地址序列，函数名相同但调用位置不同的栈不会混在一起。
完整、部分和失败的解栈结果分别统计；缺少快照的分配也保留在统计中。
最终报告不再逐笔列出分配地址和分配 ID，也不新增报告参数。

两个 ring 的到达顺序不代表调用先后，因此清理时先按全局序号排序，只对连续部分按地址
配对。已处理到的序号单独保存，不会把此前清理掉的事件误判为缺号。
程序只跟踪指定的一个进程，malloc 的序号同时作为分配 ID。

不参与计算的时间戳已删除。采集前建立 ELF 会话，停止后向 libdwfl 提供保存的寄存器和栈
副本，不读取目标进程后来变化的实时栈来补齐旧快照。模块映射变化时拒绝混用。

解栈器由主线程依次调用，不使用锁或工作线程。libdwfl 的线程回调仅用于提供
当前快照所属的 TID。符号和 CFI 查询使用普通字典缓存，关闭会话时清空；
缓存不设置条目上限，内存会随本次解栈遇到的不同地址数量增长。

`partial` 结果按已经恢复的栈帧归类，不代表未恢复的调用链尾部也相同；它与
`complete` 分开统计。缺少快照或解栈失败的分配也保留各自的字节数和次数。

栈内存从当前 RSP 起按页边界读取，遇到不可读区域或达到上限就停止。
`READ_FAULT` 表示读取失败，`LIMIT` 表示达到字节上限，都不代表已经找到栈底。
大记录预留失败时仍尝试发送基础 malloc 记录，保留分配的地址和大小。

## 范围与内存

这是短时学习测试工具。内存中保留尚未释放分配的快照、序号缺口之后尚未清理的记录，
以及自上次清理后新增的记录。若缺失事件始终未到达，缺口后的记录会一直保留。
每新增 1000 条才触发一次清理，与缓存剩余数量无关；缓存可能超过 1000 条，
因此这不是内存硬上限。

默认两个 ring 的数据区共 68 MiB，由所有 CPU 共享。malloc 记录按配置的栈上限
固定预留容量；Python 只复制有效栈前缀，不复制未使用的尾部。

只观察探针安装后的 `malloc/free`，不重建之前的分配，也没有 `calloc/realloc/mmap`
等独立探针。要求普通 glibc malloc/free 正常返回；同一线程的 malloc 重入、递归
分配器或异常跳出不在支持范围内。缺少 CFI、超出快照或达到帧数上限时不回退到
frame pointer。
